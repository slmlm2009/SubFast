## Medium Severity Issues

### Issue 1: Hardcoded Pattern Count in Test Reporter
**Location**: `tests/unified_test_reporter.py:125`  
**Finding**: Test report displays "25 episode patterns tested" instead of dynamically reading from pattern_definitions.json  
**Impact**: Misleading reporting - users see incorrect pattern count (25 vs actual 30)  
**Risk**: Low - cosmetic issue but reduces report accuracy  
**Fix**: Replace hardcoded "25" with dynamic count from JSON metadata  

```
Current: f"  ✓ Pattern Matching            : {self.integration_total_variations} variations  ({self.integration_passed}/{self.integration_total_variations} pass) - 25 episode patterns tested"
Fix needed: Read pattern count from pattern_definitions.json metadata
```

### Issue 2: Pattern 27 File Pairing Problem  
**Location**: Integration test runner file pairing logic  
**Finding**: Pattern 27 VAR1 and VAR2 tests use `[VAR11]-One Piece -0001.mkv` instead of correct `[VAR1]-One Piece -1.mkv` and `[VAR2]-One Piece -1v2.mkv`  
**Impact**: Test results don't reflect actual file variations being tested  
**Risk**: Medium - could mask real pattern recognition issues  
**Fix**: Investigate file selection logic to ensure VAR1/VAR2 use proper video files  

Evidence from directory listing shows correct files exist:
```
[VAR1]-One Piece -1.mkv ✅ (exists)
[VAR2]-One Piece -1v2.mkv ✅ (exists) 
[VAR11]-One Piece -0001.mkv ✅ (exists but wrong for VAR1/VAR2)
```

### Issue 3: Negative Test Result Messaging
**Location**: Test result reporting format  
**Finding**: Negative tests show as "pattern mismatch (expected null, got video=None, subtitle=None)" which sounds like a failure  
**Impact**: Confusing test output - negative tests are working correctly but reported as failures  
**Risk**: Low - functionality correct but reporting misleading  
**Fix**: Update messaging to clearly indicate successful negative test validation
